## 1. Ngữ cảnh & Vấn đề Cần giải quyết (Context & Problem Statement)

HopHo là trợ lý cuộc họp AI vận hành theo mô hình **Local-first** trên máy tính cá nhân. Hệ thống đòi hỏi đồng thời 3 khả năng:
1. Giao diện người dùng mượt mà, bộ cài đặt nhẹ nhàng, khởi động nhanh, chiếm ít RAM.
2. Thu nhận âm thanh chất lượng cao, trễ thấp trực tiếp từ Windows Core Audio (WASAPI loopback) và quản lý I/O tệp an toàn tuyệt đối khi gặp sự cố crash.
3. Chạy các mô hình học sâu hiện đại nhất (Speech-to-Text, Diarization, LLM, Dịch thuật), vốn có hệ sinh thái phát triển và tối ưu phong phú nhất bằng ngôn ngữ Python.

Nếu chọn **Electron**, bộ cài sẽ phình to trên $150\text{MB}$ và tốn $300-500\text{MB}$ RAM chỉ để hiển thị giao diện. Nếu chọn **Thuần Rust (Pure Rust)**, việc tích hợp các mô hình STT/Diarization mới nhất từ Hugging Face gặp rào cản rất lớn do thiếu thư viện C-bindings hoàn chỉnh. Nếu chọn **Thuần Python (PyQt/PySide)**, việc phân phối bộ cài cho người dùng phổ thông rất cồng kềnh và giao diện khó đạt độ hiện đại, linh hoạt như React/Tailwind.

## 2. Quyết định Kiến trúc (Decision)

Chúng tôi quyết định áp dụng **Kiến trúc Đa tiến trình Lai (Hybrid Multi-Process Architecture)** phân định ranh giới rõ ràng:

1. **Vỏ Desktop & Tầng Lõi Hệ thống (Shell & System Core)**: Sử dụng **Tauri 2 (Rust)** kết hợp giao diện **React 18 + TypeScript + Vite**.
   - Rust đảm nhiệm: Thu âm WASAPI native, nén Opus chunking, chủ sở hữu schema cơ sở dữ liệu SQLite, quản lý cửa sổ (cửa sổ chính và Overlay nổi always-on-top), phím tắt toàn cục và điều khiển tiến trình con.
2. **Động cơ Trí tuệ Nhân tạo (AI Computation Engine)**: Sử dụng **Python Sidecar (`hopho_sidecar`)** được đóng băng thành file thực thi độc lập (PyInstaller/Nuitka).
   - Python đảm nhiệm: Thực thi suy luận Silero VAD, CTranslate2 (Whisper), sherpa-onnx (Diarization), llama.cpp nhúng (LLM & Dịch), và trích xuất cấu trúc văn bản mẫu DOCX.
3. **Cơ chế Giao tiếp Liên tiến trình (IPC)**:
   - Giao tiếp giữa Rust và Sidecar thực hiện qua **WebSocket nội bộ bind vào `127.0.0.1`**, cấp phát cổng ngẫu nhiên và bảo vệ bằng token mật mã ngẫu nhiên sinh ra mỗi lần khởi động.
4. **Tích hợp Ngoài**: Cung cấp tiến trình độc lập **`hopho-mcp`** chạy qua `stdio`, truy cập trực tiếp SQLite (chế độ WAL) qua thư viện dùng chung `packages/hopho_store`.

## 3. Phân tích Đánh đổi: Solves / Worsens / Change it when

### 3.1 What it solves (Giải quyết được gì?)
- **Bộ cài shell siêu nhẹ**: Ứng dụng Tauri chỉ nặng (ước lượng) $\approx 15-25\text{MB}$ so với $> 150\text{MB}$ của Electron; tiêu thụ RAM nền dưới $150\text{MB}$.
- **Tận dụng trọn vẹn sức mạnh AI**: Dễ dàng tích hợp các mô hình Whisper, PhoWhisper, sherpa-onnx, llama.cpp mà không phải viết lại thuật toán.
- **Tuân thủ NFR-06 (0% CPU khi rảnh)**: Sidecar chỉ khởi động khi thực sự cần xử lý và tự động giải phóng RAM, tắt tiến trình sau 5 phút không hoạt động.
- **An toàn khi Crash (NFR-05)**: Nếu tiến trình Python AI bị lỗi bộ nhớ (OOM) thì luồng thu âm của Rust vẫn chạy liên tục, không làm mất âm thanh cuộc họp.

### 3.2 What it worsens (Gây ra bất lợi gì?)
- **Độ phức tạp trong quản lý tiến trình**: Rust Core phải đóng vai trò Watchdog giám sát sức khỏe của Sidecar, xử lý các trường hợp Sidecar crash, tự khởi động lại, và gán Windows Job Object để tránh tiến trình mồ côi.
- **Độ trễ khởi động lần đầu**: Lần đầu tiên bắt đầu phiên họp, người dùng phải đợi khoảng $1.5 - 2.5\text{ giây}$ để nạp Python Sidecar và mô hình vào bộ nhớ.
- **Bộ cài Sidecar**: Cần kỹ thuật đóng băng (freezing) cẩn thận để tránh đóng gói nhầm PyTorch full làm phình to bộ cài.

### 3.3 What would make us change it (Khi nào cần thay đổi quyết định?)
- Chúng tôi sẽ chuyển toàn bộ Sidecar sang **Thuần Rust** khi các framework học sâu trên Rust (như `candle` của Hugging Face hoặc `burn`) hỗ trợ trọn vẹn, ổn định và có hiệu năng tương đương CTranslate2 cho cả STT đa ngôn ngữ và Diarization.
- Chúng tôi sẽ chuyển WebSocket sang **Unix Domain Sockets / Windows Named Pipes** nếu có yêu cầu bảo mật ở các môi trường mạng doanh nghiệp đặc thù cấm hoàn toàn socket TCP loopback.
