# User Story: US-013 - Trích xuất cấu trúc & Điền nội dung theo mẫu biên bản tải lên

**Tầng tài liệu**: Implementation Layer (`docs/implementation/release-1/backlog/stories/US-013.md`)  
**Release**: release-1 (MVP Windows v0.1)  
**Traceability**: Map to `FR-LLM-07` trong [prd.md](../prd.md)  
**Priority**: P0 (Must)  

---

## 1. User Story Statement

**As a** Thư ký công ty có sẵn mẫu biên bản cuộc họp chuẩn của cơ quan (file Word `.docx` có logo, bảng biểu và đề mục quy định sẵn)  
**I want to** Tải file mẫu biên bản này lên để HopHo tự động nhận diện cấu trúc, dùng LLM điền nội dung cuộc họp vào và xuất ra file Word giữ nguyên mẫu biểu  
**So that** Tôi không phải mất công sao chép từng đoạn từ app sang file mẫu của công ty và đảm bảo tính tuân thủ quy chuẩn hành chính  

---

## 2. Acceptance Criteria (Given-When-Then)

### AC1: [Happy path - Tải lên mẫu biên bản và trích xuất cấu trúc thành công]
- **Given** Người dùng ở màn hình Template và bấm nút "Tải lên mẫu biên bản"
- **When** Người dùng chọn một file Word (`.docx`), Markdown (`.md`) hoặc PDF (`.pdf`) của cơ quan
- **Then** Hệ thống phân tích file mẫu, trích xuất cấu trúc các đề mục lớn, tiểu mục và các ô bảng biểu cần điền
- **And** Lưu mẫu vào bảng `templates` với `kind = 'uploaded_minutes'` và lưu file gốc vào thư mục `templates/uploaded/`

### AC2: [Happy path - LLM tự động điền nội dung vào khung mẫu đã trích xuất]
- **Given** Người dùng mở cuộc họp và chọn template mẫu biên bản vừa tải lên
- **When** Người dùng bấm "Điền biên bản theo mẫu"
- **Then** LLM đọc hiểu cấu trúc các trường thông tin trong mẫu (ví dụ: Thành phần tham gia, Nội dung báo cáo, Ý kiến giám đốc, Kết luận) và tự động trích lọc từ transcript để điền chính xác vào từng mục
- **And** Hiển thị bản xem trước (preview) văn bản đã được điền đầy đủ nội dung

### AC3: [Export Invariant - Xuất file Word giữ nguyên định dạng mẫu gốc]
- **Given** Quá trình điền nội dung hoàn tất và người dùng bấm "Xuất file DOCX"
- **When** Hệ thống tạo file đầu ra
- **Then** Tệp `.docx` xuất ra giữ nguyên vẹn logo, kiểu chữ (font), tiêu đề đầu trang/chân trang (header/footer) và cấu trúc bảng của file mẫu gốc ban đầu
- **And** Chỉ các vùng nội dung cần điền là được cập nhật thông tin mới từ cuộc họp

### AC4: [Validation & Edge Case - Tệp mẫu tải lên không trích xuất được cấu trúc]
- **Given** Người dùng tải lên một file ảnh scan dạng PDF không có text layer (hoặc file Word trống rỗng)
- **When** Bộ phân tích cấu trúc xử lý tệp
- **Then** Hệ thống phát hiện không tìm thấy cấu trúc đề mục hợp lệ, hiển thị thông báo hướng dẫn: "Không nhận diện được cấu trúc văn bản từ tệp mẫu. Vui lòng sử dụng file DOCX/PDF có chứa văn bản có thể chọn được"
- **And** Không làm gián đoạn các template có sẵn khác của hệ thống

## 3. Architecture Guardrails for Coding Agents (BẮT BUỘC ĐỌC TRƯỚC KHI CODE)

> ⛔ **Cảnh báo cho AI Coding Agent**: Trước khi sinh hoặc sửa code cho User Story này, Agent BẮT BUỘC phải đọc và tuân thủ các tài liệu kiến trúc bất biến sau:

1. **Data Model Guardrails** (`docs/architecture/05-data-architecture.md`):
   - Thao tác bảng `templates` với `kind = 'uploaded_minutes'`, lưu đường dẫn tệp mẫu gốc vào `source_file_path`.
2. **Document Processing Guardrails** (`docs/architecture/06-ai-architecture.md`):
   - Sử dụng thư viện `python-docx` để đọc và clone các thẻ paragraph/table của file mẫu, thay thế placeholder bằng nội dung sinh ra từ LLM.
3. **Design Principles & Repository Layout** (`docs/architecture/09-design-principles.md` & `10-folder-structure.md`):
   - Module trích xuất và render mẫu đặt tại `sidecar/src/hopho_sidecar/templates/extractor.py`.
