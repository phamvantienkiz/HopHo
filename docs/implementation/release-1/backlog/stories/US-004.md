# User Story: US-004 - Nhập (Import) tệp âm thanh/video có sẵn vào hệ thống

**Tầng tài liệu**: Implementation Layer (`docs/implementation/release-1/backlog/stories/US-004.md`)  
**Release**: release-1 (MVP Windows v0.1)  
**Traceability**: Map to `FR-AUD-03` trong [prd.md](../prd.md)  
**Priority**: P1 (Should)  

---

## 1. User Story Statement

**As a** Quản lý dự án có file ghi âm cuộc họp từ máy ghi âm hoặc tệp video Zoom do đồng nghiệp gửi  
**I want to** Kéo thả hoặc duyệt file âm thanh/video có sẵn vào HopHo để hệ thống tự động chuẩn hóa và xử lý  
**So that** Tôi có thể nhận diện văn bản, tách người nói và sinh tóm tắt cuộc họp mà không cần phải phát lại âm thanh qua micro  

---

## 2. Acceptance Criteria (Given-When-Then)

### AC1: [Happy path - Nhập tệp âm thanh định dạng phổ biến thành công]
- **Given** Người dùng ở màn hình chính và bấm nút "Import file" hoặc kéo thả file `.mp3`, `.wav`, `.m4a` vào cửa sổ ứng dụng
- **When** File được chọn hợp lệ
- **Then** Hệ thống gọi binary `ffmpeg` (được đóng gói sẵn kèm app) để trích xuất và chuẩn hóa luồng âm thanh về định dạng Opus 16kHz mono
- **And** Tạo một cuộc họp mới trong cơ sở dữ liệu với `status = 'recorded'`, `source = 'import'` và chuyển hướng người dùng đến màn hình chờ chạy STT/Diarization

### AC2: [Happy path - Nhập tệp video và tự động trích xuất âm thanh]
- **Given** Người dùng chọn một tệp video cuộc họp định dạng `.mp4`
- **When** Quá trình nhập bắt đầu
- **Then** `ffmpeg` tách phần âm thanh ra khỏi video, không lưu trữ video để tiết kiệm dung lượng ổ cứng
- **And** Hiển thị thanh tiến độ chuẩn hóa âm thanh (progress bar) trực quan cho người dùng

### AC3: [Validation & Edge Case - Tệp rỗng hoặc định dạng không được hỗ trợ]
- **Given** Người dùng kéo thả một tệp văn bản `.txt` hoặc tệp âm thanh bị hỏng (0 bytes)
- **When** Hệ thống kiểm tra tệp đầu vào
- **Then** Hệ thống hiển thị thông báo lỗi rõ ràng: "Định dạng tệp không được hỗ trợ hoặc tệp bị hỏng. Vui lòng chọn tệp .mp3, .wav, .m4a, .mp4"
- **And** Không tạo bản ghi rác trong cơ sở dữ liệu

### AC4: [Negative path - Tiến trình trích xuất ffmpeg gặp lỗi giữa chừng]
- **Given** Tệp video bị lỗi codec ở giữa tệp khiến ffmpeg kết thúc với exit code khác 0
- **When** Quá trình xử lý thất bại
- **Then** Hệ thống dọn dẹp các tệp tạm thời đã tạo ra, hiển thị thông báo lỗi chi tiết và đưa ứng dụng về trạng thái an toàn

## 3. Architecture Guardrails for Coding Agents (BẮT BUỘC ĐỌC TRƯỚC KHI CODE)

> ⛔ **Cảnh báo cho AI Coding Agent**: Trước khi sinh hoặc sửa code cho User Story này, Agent BẮT BUỘC phải đọc và tuân thủ các tài liệu kiến trúc bất biến sau:

1. **Data Model Guardrails** (`docs/architecture/05-data-architecture.md`):
   - Bản ghi `meetings` được tạo với `source = 'import'`, `mode = 'record_only'`.
2. **Infrastructure Guardrails** (`docs/architecture/04-deployment-architecture.md`):
   - Binary `ffmpeg` phải được đóng gói sẵn trong bộ cài app (trong thư mục resources của Tauri), không phụ thuộc vào `ffmpeg` có sẵn trên máy người dùng.
3. **Design Principles & Repository Layout** (`docs/architecture/09-design-principles.md` & `10-folder-structure.md`):
   - Logic import và gọi ffmpeg nằm trong Rust backend (`apps/desktop/src-tauri/src/recorder/import.rs`).
