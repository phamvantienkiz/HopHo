# User Story: US-012 - Sinh Tóm tắt & Action Items theo Template tiêu chuẩn

**Traceability**: Map to `FR-LLM-01`, `FR-LLM-02`, `FR-LLM-04`, `FR-LLM-06` trong [prd.md](../prd.md)  
**Priority**: P0 (Must)

## 1. User Story Statement

**As a** Quản lý dự án cần gửi báo cáo tổng kết sau cuộc họp dài cho các bên liên quan  
**I want to** Chọn một trong các mẫu tóm tắt có sẵn (Tóm tắt điều hành, Action Items, Biên bản họp chuẩn VN) hoặc mẫu tùy chỉnh để AI tự động sinh nội dung và xuất file Word/Markdown  
**So that** Tôi tiết kiệm được hàng giờ soạn thảo báo cáo mà vẫn đảm bảo đầy đủ người phụ trách và thời hạn hoàn thành các công việc  

---

## 2. Acceptance Criteria (Given-When-Then)

### AC1: [Happy path - Sinh Action Items theo cấu trúc Việc - Người - Deadline]
- **Given** Cuộc họp đã hoàn tất chạy STT bản chuẩn và người dùng chọn tab "Tổng kết & Báo cáo"
- **When** Người dùng chọn template "Action Items (Việc cần làm)" và bấm "Tạo nội dung"
- **Then** LLM phân tích toàn bộ transcript kết hợp ghi chú tay và sinh danh sách các đầu việc rõ ràng gồm 3 cột: `Nội dung công việc`, `Người phụ trách (Assignee)`, `Thời hạn hoàn thành (Deadline)`
- **And** Lưu kết quả vào bảng `outputs` và hiển thị trên màn hình với định dạng bảng Markdown đẹp mắt

### AC2: [Happy path - Sinh Biên bản cuộc họp chuẩn Việt Nam]
- **Given** Người dùng chọn template mặc định "Biên bản cuộc họp"
- **When** Người dùng yêu cầu tạo biên bản
- **Then** LLM sinh nội dung theo thể thức chuẩn: Thời gian, Địa điểm/Nền tảng, Thành phần tham dự, Nội dung các phiên thảo luận, Kết luận & Biểu quyết
- **And** Cung cấp các nút bấm: Sao chép vào Clipboard (Copy), Xuất file Markdown (`.md`), Xuất file Word (`.docx`), Xuất file PDF (`.pdf`)

### AC3: [Edge Case - Tạo mới và chỉnh sửa Template prompt tùy biến]
- **Given** Người dùng muốn có một mẫu tóm tắt riêng theo phong cách Scrum Daily hoặc 1-on-1
- **When** Người dùng vào mục Quản lý Template, bấm "Tạo mẫu mới", nhập tên và nội dung prompt Markdown (sử dụng các biến như `{{transcript}}`, `{{notes}}`, `{{speakers}}`)
- **Then** Hệ thống lưu template vào bảng `templates` với `kind = 'custom'`
- **And** Template mới xuất hiện ngay trong danh sách chọn của tất cả các cuộc họp

### AC4: [Performance & Edge Case - Xử lý cuộc họp dài 3 giờ (Map-Reduce Chunking)]
- **Given** Cuộc họp kéo dài 3 giờ khiến toàn bộ transcript vượt quá giới hạn ngữ cảnh (context window) của mô hình LLM local
- **When** Quá trình sinh tóm tắt được kích hoạt
- **Then** Sidecar tự động áp dụng chiến lược Map-Reduce: chia transcript thành các đoạn nhỏ 20-30 phút để tóm tắt ý chính từng đoạn, sau đó tổng hợp thành bản báo cáo chung
- **And** Không làm tràn bộ nhớ RAM và không gây lỗi crash tiến trình

## 3. Architecture Guardrails for Coding Agents (BẮT BUỘC ĐỌC TRƯỚC KHI CODE)

> ⛔ **Cảnh báo cho AI Coding Agent**: Trước khi sinh hoặc sửa code cho User Story này, Agent BẮT BUỘC phải đọc và tuân thủ các tài liệu kiến trúc bất biến sau:

1. **Data Model Guardrails** (`docs/architecture/05-data-architecture.md`):
   - Thao tác bảng `templates` (`id`, `name`, `kind`, `prompt_md`) và `outputs` (`id`, `meeting_id`, `template_id`, `provider`, `content_md`).
2. **AI & Prompt Guardrails** (`docs/architecture/06-ai-architecture.md`):
   - Các template mặc định được lưu dưới dạng file `.md` trong thư mục `templates/` của repo.
   - Thư viện xuất DOCX sử dụng `python-docx` để đảm bảo định dạng chuyên nghiệp.
3. **Design Principles & Repository Layout** (`docs/architecture/09-design-principles.md` & `10-folder-structure.md`):
   - Logic prompt rendering và map-reduce nằm trong `sidecar/src/hopho_sidecar/templates/` và `llm/`.
